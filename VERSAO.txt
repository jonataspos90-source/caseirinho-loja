Loja Online V9.2.0 — Multiempresa / Performance / Experiência do Cliente
Build: 2026-09-14
API esperada: 1.16.7

MULTILOJA
- O parâmetro ?empresa=<slug> define a loja ativa.
- Cada empresa recebe um link exclusivo no padrão:
  .../caseirinho-loja/?empresa=john-nome-da-empresa
- Carrinho, perfil, histórico, pedidos, avisos e cache são isolados por loja no navegador.
- O Caseirinho migra os dados locais antigos para o namespace novo sem apagar a cópia anterior.
- O PWA gera manifesto por empresa e mantém ?empresa=<slug> no start_url.
- Antes de carregar a identidade da empresa, a interface usa textos neutros de "Loja Online".

MEUS PEDIDOS / PERFORMANCE
- Clicar em Pedidos abre imediatamente usando o cache disponível.
- A sincronização ocorre depois da abertura, com indicador de atualização.
- Com sessão de histórico, uma única consulta atualiza todos os pedidos.
- Foi removido o fluxo anterior que podia fazer até 20 consultas sequenciais ao abrir Pedidos.
- Polling usa uma consulta em lote a cada 4 segundos enquanto o App está visível.
- Sem sessão de histórico, o fallback consulta no máximo 3 pedidos.
- Ao voltar para o App, o histórico é sincronizado novamente.

FRETE / EXPERIÊNCIA
- Entrega começa com horário "A combinar".
- O cliente é avisado de que o pedido terá valor de entrega.
- Cotação enviada pelo ERP aparece com valor atualizado e total atualizado.
- Cliente responde "Sim, aprovar frete" ou "Não, cancelar pedido".
- A decisão pode usar o token individual do pedido ou a sessão segura de histórico.
- Se aprovar, o ERP recebe o estado "Cliente aceitou novo frete".
- Se recusar, o pedido é cancelado e o App oferece fazer um novo pedido.
- PIX aparece depois do aceite quando a forma de pagamento é PIX.
- Horário definido posteriormente pelo ERP retorna ao App.

DADOS DO CLIENTE
- Nome, WhatsApp, e-mail, CPF e último endereço ficam preenchidos neste aparelho.
- Todos os campos permanecem editáveis.
- O histórico pode ser recuperado em outro aparelho usando WhatsApp + código de pedido.

- Sincronização do histórico usa single-flight: cliques, foco e polling simultâneos compartilham a mesma chamada em vez de duplicar requisições.
